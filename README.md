# Chelka

Виджет для выреза MacBook в духе Dynamic Island: буфер обмена с историей, музыка и состояние системы — по наведению курсора, без единого клика.

![Chelka в тёмной теме](docs/snapshots/notch-expanded-dark.png)

> **Статус: рабочая версия.** Все пять этапов готовы. Приложение собирается, запускается и делает то, что обещает.

## Возможности

- [x] Раскрытие по наведению на вырез, сворачивание при уходе курсора
- [x] Светлая, тёмная и авто-тема
- [x] Работа на дисплеях без выреза — компактный кругляш сверху
- [x] Корректное поведение при подключении мониторов и смене разрешения
- [x] **Буфер обмена**: 10 записей + 5 закреплённых, текст, ссылки, картинки, файлы
- [x] Скриншоты из папки снимков и фото с iPhone через Universal Clipboard
- [x] Перетаскивание записей мышью прямо из виджета в любое приложение
- [x] История шифруется на диске, ключ в связке ключей
- [x] Чёрный список приложений и глобальное сочетание ⌥⌘V
- [x] Мониторинг: загрузка CPU, память, температура кристалла
- [x] Музыка из любого источника: Music, Spotify, браузер, локальное видео
- [x] Окно настроек, автозапуск, понятный разбор разрешений
- [x] Русский и английский интерфейс

## Требования

- macOS 14 или новее
- Apple Silicon или Intel — приложение собирается универсальным бинарником
- Swift 6 (Command Line Tools или Xcode)

Вырез не обязателен: на обычных дисплеях виджет живёт кругляшом по центру верхней кромки.

## Сборка

```bash
git clone <репозиторий> && cd chelka
make app
open build/Chelka.app
```

Приложение подписывается ad-hoc и работает локально. После запуска ищите иконку в меню-баре — иконки в доке нет намеренно.

### Перенос на другой Mac

```bash
make dist
```

Распаковать архив, затем **правая кнопка → Открыть**. Обычный двойной клик не сработает: приложение подписано локальным сертификатом, которого на чужой машине нет.

Сборка универсальная. Если собрать только под свою архитектуру, на маке с другим процессором приложение выдаст «не поддерживается этим компьютером Mac» — при том, что и система, и подпись в порядке.

## Архитектура

```
Sources/
├── ChelkaCore/     Ядро без AppKit: геометрия, состояния, логирование.
│                   Строгая конкурентность Swift 6, покрыто тестами.
└── Chelka/         UI-слой: панель, курсор, SwiftUI-виды, меню-бар.
```

Ключевые решения:

**Геометрия выреза берётся у системы.** Размеры считаются из `safeAreaInsets` и `auxiliaryTopLeftArea`, без таблиц моделей MacBook. На одной машине вырез 209×38 pt, на другой 168×32 — код одинаковый.

**Логика решений отделена от AppKit.** Когда раскрыться, когда свернуться, как пересчитать раскладку — всё это чистые функции в `ChelkaCore`, проверяемые тестами за миллисекунды. UI-слой только доставляет события и применяет результат.

**Время монотонное, а не календарное.** Задержки наведения считаются по `ProcessInfo.systemUptime`: `Date` прыгает при синхронизации часов и подвесил бы виджет раскрытым.

**Зона наведения ниже выреза.** Внутри самого выреза курсор не виден, и целиться туда неудобно. Зона свисает на 20 точек ниже и на 10 точек шире с каждой стороны — в пустую середину меню-бара, куда легко попасть движением сверху вниз.

**На экранах без выреза виджет открывается от значка в меню-баре** — там, куда его поставил пользователь, а не по центру верхней кромки. Значок ездит, когда соседи появляются и исчезают, поэтому раскладка пересобирается, если он действительно уехал.

**Панель не крадёт клики.** Окно заведомо больше виджета — иначе анимации некуда расти. Прозрачные поля пропускают события сквозь себя, поэтому попасть в меню-бар мимо виджета невозможно.

**Снимки видов без экрана.** `make snapshots` рендерит все состояния в PNG офлайн — внешний вид проверяется в CI и в ревью, а не «у меня на макбуке выглядит нормально».

**Направление свайпа проверено логически, не руками.** `make music-demo` прогоняет реальные значения дельт через `TrackSwipeGesture` и проверяет, что порог, накопление и однократное срабатывание за жест работают правильно. Сам физический жест на трекпаде я выполнить не могу — направление (влево = вперёд) выбрано по аналогии со свайпом истории в Safari, но не подтверждено на железе.

**Буфер проверяется на живой системе.** `make clipboard-demo` кладёт в буфер настоящие данные и сверяет двенадцать утверждений: дедупликация, лимиты, закрепление, чёрный список, отсутствие самозацикливания при собственной записи и то, что история реально дошла до диска. Буфер пользователя в конце восстанавливается.

**Наведение проверяется сценарием.** `make hover-demo` водит виджет по семи положениям курсора и сверяет состояния: быстрый пролёт не раскрывает, зависание раскрывает, спуск в тело виджета не сворачивает. Позиция курсора приходит через подменяемый источник — синтезировать события мыши без разрешения «Универсальный доступ» нельзя.

## Буфер обмена

Захватывается всё, что копируется: текст, ссылки, картинки, файлы из Finder. Снимки экрана подхватываются из папки, указанной в настройках macOS, а не только с Рабочего стола. Фото и текст с iPhone приезжают через Universal Clipboard — отдельных разрешений для этого не нужно.

Клик по записи кладёт её в буфер, вставляет пользователь сам: приложение не лезет в чужие окна и не просит «Универсальный доступ». Запись можно перетащить мышью прямо в Finder, мессенджер или редактор.

**Безопасность.** История хранится в SQLite, зашифрованная AES-GCM; ключ лежит в связке ключей. Открытым текстом на диск не пишется ничего, включая превью и ключи дедупликации — в буфер попадает всё подряд, вплоть до содержимого менеджера паролей. Есть чёрный список приложений: содержимое, скопированное при активном приложении из списка, не сохраняется.

**Сочетание клавиш.** ⌥⌘V открывает виджет на истории; дальше цифры 1…9 выбирают запись, Esc закрывает. Сочетание регистрируется через Carbon и не требует разрешения «Универсальный доступ». ⌘⇧V умолчанием не взято намеренно: в Chrome, Slack и Telegram это «вставить без форматирования».

## Мониторинг

Загрузка процессора, занятая память и температура кристалла. Опрос идёт **только пока виджет раскрыт** — в свёрнутом состоянии таймеров нет вовсе, иначе виджет жёг бы батарею ради цифр, на которые никто не смотрит.

Память считается так же, как в «Мониторинге системы»: активная плюс проводная плюс сжатая, без файлового кэша. Наивное «всего минус свободно» показывало бы 90% на любом маке — macOS честно занимает свободную память под кэш и отдаёт по первому требованию.

Температура на Apple Silicon публичным API недоступна: ключи SMC, работавшие на Intel, для M-серии не отдаются. Читаем систему событий HID — тот же путь, которым идут Stats и iStat Menus; ни root, ни особых прав не нужно. Из нескольких десятков датчиков берутся `tdie` — сам кристалл; `tdev` меряют отдельные узлы, а батарея вносила бы только шум. Если API однажды закроют, виджет покажет публичный уровень теплового давления вместо градусов и продолжит работать.

## Музыка

Виджет показывает и переключает **всё, что звучит**, а не только Music и Spotify.

| Источник | Что видно | Управление |
|---|---|---|
| Music, Spotify | трек, исполнитель, обложка, позиция | напрямую |
| Браузер (YouTube, SoundCloud и прочее) | название трека, исполнитель, обложка | медиа-клавиши |
| Локальное видео, любой плеер | значок и имя приложения | медиа-клавиши, свайп |

Системный Now Playing с macOS 15.4 закрыт для сторонних приложений. Это проверено, а не взято из статьи: приватный `MediaRemote` на macOS 26.5 загружается, символы на месте, но данных не отдаёт даже при играющем звуке.

Поэтому источник определяется публичным API CoreAudio — списком процессов, выводящих звук. Разрешений он не требует. Звук выводят вспомогательные процессы (`com.apple.WebKit.GPU` вместо Safari), а их родитель — `launchd`, так что хозяина приходится восстанавливать по таблице подмен. XPC-службы при этом числятся «запущенными приложениями» наравне с обычными, поэтому отбор идёт по политике активации.

### Переключение свайпом

Два пальца на трекпаде, влево-вправо над карточкой музыки — следующий/предыдущий трек. Работает для всего сразу: Music, Spotify, браузер, локальное видео — жест просто зовёт `next()/previous()` у `MusicService`, а тот сам решает, AppleScript это или медиа-клавиша.

Наивная реализация сработала бы на каждой из десятков дельт, которые AppKit шлёт за один жест, и пролистала бы через пять треков одним движением. Вместо этого — накопительный счётчик с порогом: решение принимается один раз за жест, на кадре, где накопленная дистанция впервые пересекла порог, всё остальное до конца жеста игнорируется. Инерционные события после отрыва пальцев (`event.phase` пуст) отбрасываются целиком — иначе инерция дальше листала бы сама.

Жест ловится в `.background()` карточки, а не в `.overlay()`: SwiftUI кладёt фон позади содержимого, поэтому клики по кнопкам play/pause/next/prev долетают до них первыми, а перехватчик скролла получает событие только там, где под курсором нет интерактивного элемента.

### Что играет в браузере

Три пути, в порядке предпочтения:

1. **`navigator.mediaSession`** — тот же источник, из которого браузер рисует своё «сейчас играет». Даёт название, исполнителя и обложку для YouTube, SoundCloud, Яндекс.Музыки и всего остального. Требует разовой галочки: Safari → Настройки → Дополнения → «Показывать функции для веб-разработчиков», затем Разработка → «Разрешить JavaScript из Apple Events».
2. **Адрес вкладки** — для YouTube обложка выводится прямо из идентификатора ролика, для SoundCloud берётся через oEmbed, для остальных ищется `og:image` в разметке.
3. **Заголовок вкладки и значок приложения** — когда ничего из перечисленного недоступно.

Второй путь бессилен, когда воспроизведение идёт внутри ленты: адрес страницы при смене трека не меняется. Именно поэтому первый путь главный.

Отказы в доступе запоминаются: запрещённый запрос не повторяется каждые две секунды впустую. Сеть используется только для загрузки обложки и отключается в настройках.

Скрипты выполняются **отдельным процессом с таймаутом**. Подвисший Music.app подвесил бы `NSAppleScript` вместе с потоком, а внешний процесс просто снимается. Закрытые плееры не опрашиваются вовсе: `tell application` запустил бы их сам.

## Разрешения

Виджет ничего не выпрашивает при первом запуске. Вкладка «Разрешения» в настройках показывает, что выдано, что нет, и — главное — что именно перестаёт работать без каждого из них:

| Разрешение | Зачем | Без него |
|---|---|---|
| Связка ключей | ключ шифрования истории | история живёт до выхода из приложения |
| Папка снимков | следить за файлами снимков | снимки через ⇧⌘4 не попадут в историю |
| Управление Music и Spotify | название трека, обложка, позиция | останутся только кнопки |
| Универсальный доступ | глобальные медиа-клавиши | кнопки работают только с Music и Spotify |

### Постоянная подпись

Обязательный шаг, если собираешь приложение сам:

```bash
make identity
```

Без него разрешения теряются после каждой пересборки — причём галочка в списке остаётся включённой, а система приложение всё равно не признаёт. Причина видна в требовании к подписи:

| Подпись | Требование | Что это значит |
|---|---|---|
| ad-hoc | `designated => cdhash H"…"` | меняется при каждой сборке |
| сертификат | `designated => identifier "com.ivan.chelka" and certificate leaf = H"…"` | не меняется никогда |

Сертификат самоподписанный и локальный: он ничего не подтверждает посторонним и нужен только чтобы личность приложения была постоянной. Удаляется одной командой — `security delete-certificate -c "Chelka Dev"`.

После первой сборки с сертификатом разрешения нужно выдать заново один раз: старые записи в списке относятся к прошлым сборкам.
